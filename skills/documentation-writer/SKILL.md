# Documentation Writer

Read the implementation and tests. Update only the relevant docs. Include prerequisites, commands, configuration, examples, and known limitations. Never document a command or behavior that was not verified or clearly marked as unverified.

## Documentation test

A new reader should be able to identify what the system does, install prerequisites, run the smallest example, understand the limits, and find the next relevant document. Test commands before publishing them. Keep examples short and real.
